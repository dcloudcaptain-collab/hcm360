5. AI/ML OPPORTUNITIES
──────────────────────

IMMEDIATE (Phase 1):

  1. RETENTION RISK SCORING
     Input Features:
       • Tenure (years employed)
       • Department & position
       • Promotion history (promotions in last 2 years)
       • Training participation (training hours per year)
       • Performance rating trend
       • Leave usage pattern (spikes in sick leave)
       • Salary vs. market average

     Model: Logistic Regression or Random Forest
     Output: Risk Score (0-100)
       • 0-30: Low risk (retain)
       • 31-60: Medium risk (monitor)
       • 61-100: High risk (intervene)

     Action: HR gets alerts for high-risk employees; recommend:
       • Career development plan
       • Salary review
       • Mentorship pairing
       • Promotion consideration

  2. SKILL GAP IDENTIFICATION
     Input:
       • Job requirements (per position)
       • Employee training history
       • Certifications held
       • Performance ratings by competency

     Output: Skill gaps per employee/position
       • Missing critical skills
       • Recommended training programs
       • Timeline to fill gap

  3. SUCCESSION PLANNING
     Input:
       • Performance ratings (top performers)
       • Tenure & readiness for next level
       • Training completion (leadership programs)
       • Promotion frequency
       • Critical position definition

     Output: Succession candidates ranked
       • Ready now (0-6 months)
       • Ready soon (6-12 months)
       • Development needed (1-2 years)

SHORT TERM (Phase 2):

  4. CHATBOT / AI ASSISTANT
     Natural Language Interface:
       ❯ "How many vacation days do I have?"
         → Query leave_balance table with auth check
       ❯ "What's my current salary?"
         → Query compensation table (masked for privacy)
       ❯ "When is my next training scheduled?"
         → Query training_records
       ❯ "How do I request leave?"
         → Guided workflow
       ❯ "What's my promotion timeline?"
         → Based on succession plan data

     Benefits: Reduce HR support tickets 30-40%

  5. ANOMALY DETECTION
     Monitor for:
       • Unusually high overtime in a department
       • Sudden spike in leave requests
       • Salary adjustments outside normal range
       • Unauthorized access to sensitive records
       • Unusually high absenteeism

     Alert HR/Compliance for review

  6. WORKLOAD FORECASTING
     Predict staffing needs:
       • Historical turnover rates
       • Retirement eligibility timeline
       • Department growth plans
       • Seasonal hiring patterns

     Output: Recruitment plan (6-12 months ahead)

MEDIUM TERM (Phase 3):

  7. PERFORMANCE PREDICTION
     Predict which employees will achieve goals
     Input: Historical performance data, current metrics
     Use: Resource allocation, stretch assignment identification

  8. COMPENSATION BENCHMARKING
     Compare internal salary structure vs. market
     Recommend salary adjustments for retention

  9. TRAINING ROI ANALYSIS
     Measure training impact on:
       • Performance improvement
       • Turnover reduction
       • Skill acquisition

6. SECURITY & COMPLIANCE
────────────────────────

POSTGRESQL BUILT-IN SECURITY:

  ✓ Row-Level Security (RLS) Policies
    • Employees can only view their own records
    • Managers can view team data
    • HR can view all records (with audit trail)
    • No sensitive salary data for non-HR users

  ✓ Encryption
    • pgcrypto: Sensitive fields (SSN, banking)
      CREATE EXTENSION pgcrypto;
      • gsis_number ENCRYPTED
      • pagibig_number ENCRYPTED
      • sss_number ENCRYPTED
      • tin_number ENCRYPTED

    • SSL/TLS: All connections encrypted in transit

  ✓ Audit Trail
    • audit_logs: Append-only table
    • All INSERT, UPDATE, DELETE logged automatically
    • Change reason & user captured
    • No ability to delete audit logs

  ✓ Access Control
    • Database roles: hr_read, hr_write, hr_admin, manager_read, employee_read
    • GRANT SELECT ON employees TO hr_read;
    • GRANT INSERT, UPDATE ON attendance TO manager_write;

CREATE TABLE departments (
  dept_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dept_code VARCHAR(20) UNIQUE NOT NULL,
  dept_name VARCHAR(150) NOT NULL,
  parent_dept_id UUID REFERENCES departments(dept_id) ON DELETE SET NULL,
  head_id UUID REFERENCES employees(emp_id) ON DELETE SET NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted_at TIMESTAMP NULL
);

CREATE INDEX idx_departments_parent ON departments(parent_dept_id);
CREATE INDEX idx_departments_head ON departments(head_id);

──────────────────────────────────────────────────────────────────────────────

CREATE TABLE employees (
  emp_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  emp_number VARCHAR(20) UNIQUE NOT NULL,
  first_name VARCHAR(100) NOT NULL,
  middle_name VARCHAR(100),
  last_name VARCHAR(100) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  gender CHAR(1) CHECK (gender IN ('M', 'F', 'O')) NOT NULL,
  birthdate DATE,
  civil_status VARCHAR(30),
  citizenship VARCHAR(50),
  blood_type VARCHAR(3),
  hire_date DATE NOT NULL,
  original_appointment_date DATE,
  employment_status VARCHAR(30) DEFAULT 'Active',
  employment_type VARCHAR(30),
  phone_number VARCHAR(20),
  address TEXT,
  emergency_contact_name VARCHAR(100),
  emergency_contact_phone VARCHAR(20),
  department_id UUID REFERENCES departments(dept_id),
  position_id UUID REFERENCES positions(pos_id),
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  deleted_at TIMESTAMP NULL
);

CREATE INDEX idx_employees_emp_number ON employees(emp_number);
CREATE INDEX idx_employees_email ON employees(email);
CREATE INDEX idx_employees_hire_date ON employees(hire_date);
CREATE INDEX idx_employees_birthdate ON employees(birthdate);
CREATE INDEX idx_employees_dept ON employees(department_id);
CREATE INDEX idx_employees_pos ON employees(position_id);
CREATE INDEX idx_employees_status ON employees(employment_status);

──────────────────────────────────────────────────────────────────────────────

CREATE TABLE audit_logs (
  log_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  schema_name VARCHAR(100) NOT NULL,
  table_name VARCHAR(100) NOT NULL,
  record_id VARCHAR(100) NOT NULL,
  action VARCHAR(10) CHECK (action IN ('INSERT', 'UPDATE', 'DELETE')),
  old_values JSONB,
  new_values JSONB,
  changed_by VARCHAR(100) NOT NULL,
  changed_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  change_reason TEXT,
  ip_address INET
);

-- Audit logs: append-only, no deletes
ALTER TABLE audit_logs ENABLE ROW LEVEL SECURITY;
CREATE POLICY no_delete_audit ON audit_logs AS RESTRICTIVE FOR DELETE USING (FALSE);

CREATE INDEX idx_audit_logs_table ON audit_logs(table_name, record_id);
CREATE INDEX idx_audit_logs_changed_at ON audit_logs(changed_at);
